# Minimal runtime for the QUANTUM resource-estimation HPC shards (Python 3.10).
# Pinned to the versions the laptop reference runs were validated against
# (mirrors the repo-root requirements.txt quantum stack).
#
# This is the quantum counterpart of hpc/detsvsL/requirements-hpc.txt and is a
# HEAVIER, riskier tree than the classical one — pyLIQTR pulls cirq/qualtran plus
# juliacall/juliapkg (which can try to auto-provision a Julia runtime on first
# import) and gmpy2 (needs GMP/MPFR). SMOKE-TEST ON A qis NODE FIRST:
#     python -m misc.run_quantum_shard --test
# which imports pyLIQTR through a real L=2 A=1 estimate and surfaces any Julia /
# GMP provisioning problem before a real campaign is launched.
#
# NO C++ build step (unlike the classical shard): evaluate_resources is pure
# Python/numpy symbolic resource counting — there is no compiled hot path.
#
# scipy is needed for the 'tong' boson-cutoff series (sparse / ns): the tong
# cutoff imports classical.trimci.tong_bound, whose package __init__ eagerly
# imports the solver modules — but those only need numpy + scipy AT IMPORT TIME
# (the compiled mixed_ci backend and the official `trimci` package are lazy,
# function-level, and never triggered by the pure-math cutoff call). openfermion
# pulls scipy transitively anyway; pinning it keeps the tong import deterministic.
# Two hard-won pins from the smoke-test iterations (2026-08-03, qis3):
#
#  * qualtran==0.4.0 — pyLIQTR 1.3.4 does NOT pin qualtran, so an unpinned install
#    resolves a NEWER qualtran whose `CtrlSpec` is a slotted attrs class with no
#    __dict__, so `functools.cached_property` on `.shapes` raises `TypeError: No
#    '__dict__' attribute on 'CtrlSpec'` inside the walk-operator t_complexity
#    estimate (smoke test 290356: Lambda computed, then the T-count died). 0.4.0 is
#    the laptop-validated version and works with a modern attrs — the qualtran
#    VERSION was the bug, not attrs (do NOT pin attrs; see below).
#
#  * cirq-core==1.4.0 (NOT the `cirq` metapackage) — pyLIQTR/openfermion depend on
#    cirq-core; the full `cirq` metapackage additionally drags in cirq-rigetti ->
#    pyquil -> attrs>=20,<22, which is UNSATISFIABLE against the modern attrs that
#    qualtran 0.4.0 pulls (smoke test 290357). The laptop env has only cirq-core.
pyLIQTR==1.3.4
qualtran==0.4.0
openfermion==1.6.1
numpy==1.26.4
scipy==1.12.0
cirq-core==1.4.0
matplotlib==3.10.9
